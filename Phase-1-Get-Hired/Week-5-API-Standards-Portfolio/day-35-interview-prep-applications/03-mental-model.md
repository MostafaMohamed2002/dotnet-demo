# MENTAL MODEL CHECK

## The Analogy: The Courtroom Testimony
An interview is not a "coding test"; it is a **Courtroom Testimony**.

The interviewer is the judge. Your "knowledge" is your testimony. But testimony is weak without **Evidence**.
- **Weak Answer**: "I know how to use DI." (Testimony only).
- **Strong Answer**: "I implemented DI in my Clinic project. I used `AddScoped` for my `DbContext` to ensure that all services in a single request shared the same database transaction, preventing data inconsistency." (Testimony + Evidence).

## Where the Analogy Breaks Down
In a courtroom, you are discouraged from talking too much. In an interview, you must find the balance between "concise" and "detailed." If you provide evidence too early, you might reveal a mistake you didn't want to discuss. If you provide it too late, the interviewer might have already decided you don't know the concept.
